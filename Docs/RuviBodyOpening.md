# Автоматическое открытие корпуса Руви и случайные реакции

При каждом новом открытии один раз выбирается реакция:

| Реакция | Шанс | Состояние слоя Base Layer |
| --- | --- | --- |
| Open1 | 50% | RUVI_Open |
| Open2 | 22,5% | RUVI_Open2 |
| Open3 | 22,5% | RUVI_Open3 |
| FuckOff | 5% | RUVI_Special(FuckOff) |

Названия состояний задаются в контроллере презентации. Все четыре состояния уже
есть в RuviBody. Дополнительные переходы и Trigger не нужны. Reaction Override
по умолчанию Random; для проверки выберите Open1, Open2, Open3 или FuckOff.
После проверки верните Random. Повторное нажатие во время движения не меняет
выбранную реакцию. Во время открытия оно отменяет вызов: в ближайшем LateUpdate
текущий клип корпуса проигрывается назад от достигнутой позы до закрытой крышки,
после чего начинается возврат за спину. Доигрывания открытия и включения предметов
нет. Возврат не запускается одновременно с крышкой, иначе событие скрытия может
оборвать её закрытие. Для обычного закрытия уже
открытого инвентаря сохраняется полное обратное Open1 перед возвратом.
Готовность обоих движений обрабатывается в LateUpdate, после обновления Animator.
Событие готовности только устанавливает флаг; обратная выборка поз начинается
на следующем кадре, чтобы не вызывать Animator.Update из Animation Event.
Нажатия во время закрытия не запускают новые движения.
Роботы без отдельного Animator корпуса сохраняют старое поведение.

При FuckOff контроллер ждёт завершения жеста и готовности вылета, затем запускает
возврат за спину без обратного Open1. OpenCompleted не вызывается, предметы и ввод
инвентаря не включаются. CloseCompleted после скрытия освобождает управление через
существующий InventoryInputController3D; дополнительно испускается OpenRejected.
Страховочный таймаут вылета не превращает отказ в успешное открытие.

`InventoryRobotPresentationController` управляет двумя Animator:

- Animator: существующий вылет и возврат, параметры OpenInventory / CloseInventory.
- Body Animator: Animator новой модели с контроллером RuviBody.

В префабе `Assets/Failsafe/Inventory/Ruvi/InventoryRobotPresentation (1).prefab`
Body Animator уже назначен. Для существующих экземпляров без этой ссылки код
находит вложенный Animator с контроллером, названным `RuviBody`.

Body Open State = `Base Layer.RUVI_Open` (имя состояния, не имя FBX-клипа).
Body Open Speed = 1. Body Opening Timeout = 10 секунд реального времени.
Состояние должно содержать незакольцованный клип Open1, без автоматического
выходящего перехода. Trigger Open1 и переход из Closed можно оставить для
ручной проверки: игровой код запускает состояние непосредственно через Play.

При открытии одновременно запускаются вылет и корпус. Событие
NotifyInventoryReady из старого клипа теперь означает только готовность вылета.
Предметы и ввод включаются лишь после завершения обоих движений. Старый таймаут
вылета не обходит ожидание корпуса. Последняя поза корпуса фиксируется.
Время корпуса задаёт контроллер: он выбирает позы от 0 до 1 по длительности
клипа и Body Open Speed. Готовность устанавливается после выборки последнего
кадра, без ожидания normalizedTime от автоматически работающего Animator.
События FBX при выборке поз не вызываются; предметы и взаимодействие по-прежнему
включаются через OpenCompleted после готовности корпуса и вылета.

При закрытии сначала проигрывается Open1 в обратном направлении, затем прежний
возврат за спину. Body Close Source State = `Base Layer.RUVI_Open`, независимо
от варианта открытия. Body Close Speed задаёт скорость закрытия (по умолчанию 1).
Первый кадр фиксируется до возврата. Rebind не используется, чтобы не сбрасывать
Transform прикреплённого UI. Код последовательно уменьшает время состояния,
не используя отрицательный Animator.speed; Animation Events при этом отключены
только на время выборки позы. Отдельных стрелок или клипа Close создавать не нужно.
При добавлении других открытий нужно проверить совместимость конечных поз с
последней позой Open1: автоматического смешивания между ними пока нет.
Body Closing Timeout ограничивает ожидание закрытия корпуса; таймаут возврата
начинает отсчитываться только после него. Старое событие скрытия не может
пропустить закрытие корпуса.

Возврат запускается напрямую через состояние Return State (`Base Layer.Closing`),
а его завершение проверяется отдельно от Animation Event. Если такого состояния
нет, используется прежний Trigger CloseInventory. В стандартном контроллере
переход Closing → Hidden теперь начинается в конце клипа, а не на 75%.

Если состояние корпуса не найдено, открытие отклоняется. Если корпус не завершил
анимацию за таймаут, робот скрывается, а существующий обработчик CloseCompleted
освобождает управление и курсор. Повторная команда во время открытия отменяет
вызов, а во время закрытия игнорируется и не перезапускает анимации или таймеры.

Проверка в Unity: открыть инвентарь без ручного Trigger; дождаться предметов;
закрыть; открыть снова несколько раз. Проверить, что UI и предметы совпадают,
первая поза корпуса не вспыхивает перед камерой и управление возвращается.
